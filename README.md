# SillyTavern-MiMoTTS

把 **小米 MiMo 语音合成**（`mimo-v2.5-tts` 系列）接入 SillyTavern 的 TTS 供应商扩展。
安装后，酒馆 TTS 面板的 Provider 下拉框里会多出 **MiMo** 一项。

> 当前版本 **v2.0.0**：把原先的自用完整版合并进来（中转备用 / 分段流水线 / 5xx 重试 / 空文本保护）。
> 此后只维护这一个仓库。

---

## 功能

| 功能 | 状态 | 说明 |
|---|---|---|
| 预置音色合成 | ✅ | `冰糖` `茉莉` `苏打` `白桦` `Mia` `Chloe` `Milo` `Dean` |
| 整段播放（推荐） | ✅ | 非流式拿单个完整 MP3，零卡顿 |
| 分块流式播放 | ✅ | pcm16 + 本地封 WAV，首音快但块间有停顿 |
| 分段流水线 | ✅ | 长文本按句切分、逐批请求、边到边播，抢首音 |
| 在途请求取消 | ✅ | 切换消息/停止播放时中止旧请求，避免"两条一起读" |
| 中转备用模式 | ✅ | 直连不可用时经服务器转发 |
| 5xx 自动重试 / 空文本保护 | ✅ | MiMo 偶发 500；整条都是元数据块时直接跳过 |

## 安装

```bash
cd <SillyTavern>/data/<user>/extensions
git clone https://github.com/ymf2317-tech/SillyTavern-MiMoTTS.git mimo-tts
```

也可以放进 `public/scripts/extensions/third-party/mimo-tts/`，然后硬刷新页面（Ctrl+Shift+R）。

## ⚠️ 先读这里：必须这样配，否则标签会被念出来

酒馆的文本清洗发生在「按段朗读」切段**之后**，而且是**逐行执行**的。
所以只要开着「按段朗读」，**跨行正则必然静默失效** —— 标签块、元数据会被一字一句念出来。

| 设置项 | 值 | 为什么 |
|---|---|---|
| **按段朗读** | **关** | 开着会让清洗逐行执行，跨行正则失效 |
| **跳过标签块内容** | **关** | 它自带的正则太粗糙，整段模式下会把正文一起吃光 |
| **应用正则过滤** | **开** | 填你需要的过滤规则（可过滤思维链、`<tag>` 块等） |
| **分段流水线**（本扩展） | **开** | 补回关掉按段朗读后损失的延迟 |
| **播放方式** | **整段播放** | 分块流式每块都要换音源，必然有间断 |

## 密钥"不保存"？大概率不是扩展的问题

酒馆保存设置的方式是**内存态整体回写 + 1 秒防抖**，且 `beforeunload` **不保存**。所以：

- 粘贴 Key 后立刻 Ctrl+R / 关页面（<1s）→ 没落盘；
- **开两个标签页**，在旧标签页改任何设置 → 1 秒后把整份旧设置写回，Key 被覆盖成空。

本扩展在面板底部加了「设置已保存 HH:MM:SS」提示，可以看到保存确实发生了。

## 开发者说明（踩坑记录）

- **流式 MP3 每块自带 Xing 头帧**：`stream:true` 时每个 SSE 块都是一个带 Xing 帧的 MP3 片段，
  拼起来就是几十个空帧 → 播放时每 0.3 秒"突"一下。所以整段播放必须走 `stream:false`；
  要分块就改用 `pcm16` 并本地封 WAV（无帧结构，可任意切割）。
- **酒馆播放器每块换一次音源**（`getBase64Async` → 换 `.src` → `canplay` → `play`），
  移动端每次 0.3~0.5s。推论：分 N 块必卡 N-1 次，零卡顿与低延迟不能兼得。
- **酒馆没有"取消"事件**：`resetTtsPlayback()` 只清队列，不会通知供应商。
  本扩展用 newest-wins：新请求一来就 `abort()` 上一个。
- **voicemap 存的是显示名，`generateTts` 收到的是 `voice_id`**，两者都要接住。
